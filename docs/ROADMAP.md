# COGnito v1.0 로드맵

## 비전

COG URL을 직접 입력하는 단순 뷰어에서, **공개 COG 영상을 자동 수집·탐색·공유할 수 있는 플랫폼**으로 진화한다.

## 아키텍처 결정

| 결정 | 선택 | 근거 |
|------|------|------|
| 백엔드 | Supabase (BaaS) | 서버 코드 최소화. Auth/DB/Storage 통합. 오픈소스. |
| 인증 | GitHub·Google OAuth | 별도 회원가입 불필요. Supabase Auth 기본 지원. |
| COG 수집 | STAC 자동 + 수동 등록 | STAC은 표준 API로 확장성 확보, 수동 등록은 유연성 확보. |
| 프론트엔드 | 기존 Vite + OpenLayers 유지 | 안정적인 기존 뷰어 위에 기능 확장. |

## 콘텐츠 철학

**"포맷이 맞으면 수집"이 아니라 "사람들과 나눌 가치가 있는 영상"을 수집한다.**

COGnito에 등록되는 영상은 기술적으로 렌더링 가능한지가 아니라, *의미*가 있는지를 기준으로 선별한다.

- 영상 하나하나에는 제목, 배경 설명, 촬영 맥락이 따라붙어야 한다.
- "이게 왜 흥미로운가?"에 답할 수 없는 영상은 등록하지 않는다.
- STAC 자동 수집이라도 맹목적인 bulk import는 하지 않는다. 수집 기준은 항상 "사람에게 보여줄 만한가?"이다.

이 원칙은 카탈로그 설계와 이후 모든 콘텐츠 수집 작업에 적용된다.

```
  id, provider, display_name, avatar_url, created_at

  crs, bands, bbox, thumbnail_url, metadata_json,
  captured_at, region, sensor, resolution, tags,
  created_at

likes
  user_id, cog_image_id, created_at

  id, user_id, name, created_at

  watchlist_id, cog_image_id, added_at
```

## Post-v1.0 로드맵

v1.0 이후 사용자 피드백과 우선순위에 따라 추진할 기능.

- Service Worker 고도화 (현재 기본 앱 셸 캐싱만 구현)
- 오프라인 상태 감지 및 폴백 UI
- 타일 캐싱 전략

### 테스트 강화

- 유닛 테스트 추가 (핵심 모듈: cogLayer, cogImageLayer, STAC 클라이언트)
- 신규 기능 E2E 테스트

### 성능 최적화

- 성능 프로파일링 (번들 크기, 초기 로딩 속도)
- Lighthouse 성능 점수 80+ 목표
